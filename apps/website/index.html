Every unit and building below is drawn live in your browser by the game's own sprite code: plain shapes and solid team colours, so you can tell a Heavy Tank from a Mammoth at a glance. The game ships no image files at all.

How it works

One deterministic simulation, shared by every player. The browser draws it, the server only relays orders.

  1. Rules from OpenRA

    OpenRA's Red Alert YAML is extracted into a catalog, then gen_rules.py writes rules.json, embedded in the engine.

  2. Rust simulation

    The webra-sim crate runs 25 fixed ticks per second with integer math only: 1024 units per cell, an integer sine table and a seeded RNG.

  3. WebAssembly

    Compiled with wasm-pack. Rust writes instance data into flat buffers that go straight from WebAssembly memory to the GPU.

  4. WebGPU renderer

    WGSL shaders draw terrain, instanced sprites with team colour masks and fog of war. Sprites are generated with Canvas2D at startup.

Multiplayer

Model
Deterministic lockstep: every client runs the same simulation, only orders travel.
Server
A Cloudflare Worker with one Durable Object per game session. It relays orders and never runs the game.
Safety
Orders are stamped with the sender, validated and rate limited. State hashes every 25 ticks catch desyncs.

Engine

Pathfinding
Flow fields per goal and locomotor, cached and shared by every unit with the same destination.
Queries
A spatial hash rebuilt every tick serves separation, targeting and splash damage.
Maps
Plain JSON maps identified by a SHA-256 hash, so every player provably runs the same battlefield.

Standing on the shoulders of giants

OpenRA

OpenRA is the open-source reimplementation of the classic Westwood strategy games. WebRA's gameplay values (costs, build times, health, armour, weapons, prerequisites and timing) come from OpenRA's mods/ra rules, licensed under the GPLv3. Many thanks to the OpenRA contributors.

Westwood Studios

For the original Command & Conquer: Red Alert (1996), the game that inspired all of this.
